# Visual system

## Purpose

The portfolio should feel creative, elegant, and technically credible without looking like a generic dashboard or an imitation IDE.

## Composition

- Use a clear editorial grid with connected sections and controlled density.
- Reserve portrait space on the first CV view without making the image mandatory.
- Use subtle chain, path, or relationship motifs to connect background, projects, evidence, and learning trajectory.
- Treat code and terminal material as authentic readable excerpts, not decorative screenshots.
- Separate overview, detail, commentary, and evidence through spacing, labels, tone, and surface treatment.

## Typography

Use no more than three type families: display, body, and monospace. Prefer system or openly licensed web fonts with robust fallbacks. Contrast and line length take priority over novelty.

## Responsive and print policy

Essential facts never disappear at smaller widths. Multi-column layouts linearize deliberately. Print excludes navigation and controls without print meaning, preserves URLs where useful, avoids splitting compact evidence units, and does not rely on background color for meaning.

## Accessibility

Semantic headings, landmarks, focus order, visible focus, accessible names, meaningful alternatives, reduced-motion behavior, text selection, zoom resilience, and non-color distinctions are release requirements.
